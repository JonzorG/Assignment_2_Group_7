      10             :  * A `LazyFunction` encapsulates a computation which has inputs, outputs and potentially side
      11             :  * effects. Most importantly, a `LazyFunction` supports laziness in its inputs and outputs:
      12             :  * - Only outputs that are actually used have to be computed.
      13             :  * - Inputs can be requested lazily based on which outputs are used or what side effects the
      14             :  *   function has.
      15             :  *
      16             :  * A lazy-function that uses laziness may be executed more than once. The most common example is
      17             :  * the geometry nodes switch node. Depending on a condition input, it decides which one of the
      18             :  * other inputs is actually used. From the perspective of the switch node, its execution works as
      19             :  * follows:
      20             :  * 1. The switch node is first executed. It sees that the output is used. Now it requests the
      21             :  *    condition input from the caller and exits.
      22             :  * 2. Once the caller is able to provide the condition input the switch node is executed again.
      23             :  *    This time it retrieves the condition and requests one of the other inputs. Then the node
      24             :  *    exits again, giving back control to the caller.
      25             :  * 3. When the caller computed the second requested input the switch node executes a last time.
      26             :  *    This time it retrieves the new input and forwards it to the output.
      27             :  *
      28             :  * In some sense, a lazy-function can be thought of like a state machine. Every time it is
      29             :  * executed, it advances its state until all required outputs are ready.
      30             :  *
      31             :  * The lazy-function interface is designed to support composition of many such functions into a new
      32             :  * lazy-functions, all while keeping the laziness working. For example, in geometry nodes a switch
      33             :  * node in a node group should still be able to decide whether a node in the parent group will be
      34             :  * executed or not. This is essential to avoid doing unnecessary work.
      35             :  *
      36             :  * The lazy-function system consists of multiple core components:
      37             :  * - The interface of a lazy-function itself including its calling convention.
      38             :  * - A graph data structure that allows composing many lazy-functions by connecting their inputs
      39             :  *   and outputs.
      40             :  * - An executor that allows multi-threaded execution or such a graph.
      41             :  */
