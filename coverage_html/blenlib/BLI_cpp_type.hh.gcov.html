       8             :  * \ingroup bli
       9             :  *
      10             :  * The `CPPType` class allows working with arbitrary C++ types in a generic way. An instance of
      11             :  * #CPPType wraps exactly one type like `int` or `std::string`.
      12             :  *
      13             :  * With #CPPType one can write generic data structures and algorithms. That is similar to what C++
      14             :  * templates allow. The difference is that when using templates, the types have to be known at
      15             :  * compile time and the code has to be instantiated multiple times. On the other hand, when using
      16             :  * #CPPType, the data type only has to be known at run-time, and the code only has to be compiled
      17             :  * once. Whether #CPPType or classic c++ templates should be used depends on the context:
      18             :  * - If the data type is not known at run-time, #CPPType should be used.
      19             :  * - If the data type is known to be one of a few, it depends on how performance sensitive the code
      20             :  *   is.
      21             :  *   - If it it's a small hot loop, a template can be used to optimize for every type (at the
      22             :  *     cost of longer compile time, a larger binary and the complexity that comes from using
      23             :  *     templates).
      24             :  *   - If the code is not performance sensitive, it usually makes sense to use #CPPType instead.
      25             :  * - Sometimes a combination can make sense. Optimized code can be generated at compile-time for
      26             :  *   some types, while there is a fallback code path using #CPPType for all other types.
      27             :  *   #CPPType::to_static_type allows dispatching between both versions based on the type.
      28             :  *
      29             :  * Under some circumstances, #CPPType serves a similar role as #std::type_info. However, #CPPType
      30             :  * has much more utility because it contains methods for actually working with instances of the
      31             :  * type.
      32             :  *
      33             :  * Every type has a size and an alignment. Every function dealing with C++ types in a generic way,
      34             :  * has to make sure that alignment rules are followed. The methods provided by a #CPPType instance
      35             :  * will check for correct alignment as well.
      36             :  *
      37             :  * Every type has a name that is for debugging purposes only. It should not be used as identifier.
      38             :  *
      39             :  * To check if two instances of #CPPType represent the same type, only their pointers have to be
      40             :  * compared. Any C++ type has at most one corresponding #CPPType instance.
      41             :  *
      42             :  * A #CPPType instance comes with many methods that allow dealing with types in a generic way. Most
      43             :  * methods come in three variants. Using the default-construct methods as an example:
      44             :  *  - `default_construct(void *ptr)`:
      45             :  *      Constructs a single instance of that type at the given pointer.
      46             :  *  - `default_construct_n(void *ptr, int64_t n)`:
      47             :  *      Constructs n instances of that type in an array that starts at the given pointer.
      48             :  *  - `default_construct_indices(void *ptr, const IndexMask &mask)`:
      49             :  *      Constructs multiple instances of that type in an array that starts at the given pointer.
      50             :  *      Only the indices referenced by `mask` will by constructed.
      51             :  *
      52             :  * In some cases default-construction does nothing (e.g. for trivial types like int). The
      53             :  * `default_value` method provides some default value anyway that can be copied instead. What the
      54             :  * default value is, depends on the type. Usually it is something like 0 or an empty string.
      55             :  *
      56             :  *
      57             :  * Implementation Considerations
      58             :  * -----------------------------
      59             :  *
      60             :  * Concepts like inheritance are currently not captured by this system. This is not because it is
      61             :  * not possible, but because it was not necessary to add this complexity yet.
      62             :  *
      63             :  * One could also implement CPPType itself using virtual methods and a child class for every
      64             :  * wrapped type. However, the approach used now with explicit function pointers to works better.
      65             :  * Here are some reasons:
      66             :  *  - If CPPType would be inherited once for every used C++ type, we would get a lot of classes
      67             :  *    that would only be instanced once each.

      69             :  *    one necessary indirection using function pointers adds a lot of overhead. If all methods were
      70             :  *    virtual, there would be a second level of indirection that increases the overhead even more.
      71             :  *  - If it becomes necessary, we could pass the function pointers to C functions more easily than
      72             :  *    pointers to virtual member functions.
