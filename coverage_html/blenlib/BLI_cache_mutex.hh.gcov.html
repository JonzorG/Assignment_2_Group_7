      13             :  * Using #CacheMutex instead of a "raw mutex" to protect a cache has some benefits:

      15             :  * - Cleaner and less redundant code because the same locking patterns don't have to be repeated
      16             :  *   everywhere.

      18             :  *   mentioned below.
      19             :  *
      20             :  * The data protected by #CacheMutex is not part of #CacheMutex. Instead, the #CacheMutex and its
      21             :  * protected data should generally be placed next to each other.
      22             :  *
      23             :  * Each #CacheMutex protects exactly one cache, so multiple cache mutexes have to be used when a
      24             :  * class has multiple caches. That is contrary to a "custom" solution using `Mutex` where one
      25             :  * mutex could protect multiple caches at the cost of higher lock contention.
