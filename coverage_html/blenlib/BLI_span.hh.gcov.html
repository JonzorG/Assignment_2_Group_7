      10             :  * An `Span<T>` references an array that is owned by someone else. It is just a
      11             :  * pointer and a size. Since the memory is not owned, Span should not be used to transfer
      12             :  * ownership. The array cannot be modified through the Span. However, if T is a non-const
      13             :  * pointer, the pointed-to elements can be modified.
      14             :  *
      15             :  * There is also `MutableSpan<T>`. It is mostly the same as Span, but allows the
      16             :  * array to be modified.
      17             :  *
      18             :  * A (Mutable)Span can refer to data owned by many different data structures including
      19             :  * Vector, Array, VectorSet, std::vector, std::array, std::string,
      20             :  * std::initializer_list and c-style array.
      21             :  *
      22             :  * `Span` is very similar to `std::span` (C++20). However, there are a few differences:
      23             :  * - `Span` is const by default. This is to avoid making things mutable when they don't
      24             :  *   have to be. To get a non-const span, you need to use `MutableSpan`. Below is a list
      25             :  *   of const-behavior-equivalent pairs of data structures:
      26             :  *   - std::span<int>                <==>  MutableSpan<int>
      27             :  *   - std::span<const int>          <==>  Span<int>
      28             :  *   - std::span<int *>              <==>  MutableSpan<int *>
      29             :  *   - std::span<const int *>        <==>  MutableSpan<const int *>
      30             :  *   - std::span<int * const>        <==>  Span<int *>
      31             :  *   - std::span<const int * const>  <==>  Span<const int *>
      32             :  * - `Span` always has a dynamic extent, while `std::span` can have a size that is
      33             :  *   determined at compile time. I did not have a use case for that yet. If we need it, we can
      34             :  *   decide to add this functionality to `Span` or introduce a new type like
      35             :  *   `FixedSpan<T, N>`.
      36             :  *
      37             :  * `Span<T>` should be your default choice when you have to pass a read-only array
      38             :  * into a function. It is better than passing a `const Vector &`, because e.g. then the function
      39             :  * only works for vectors and not arrays. Using Span as function parameter makes it usable in more
      40             :  * contexts, better expresses the intent and does not sacrifice performance. It is also better than
      41             :  * passing a raw pointer and size separately, because it is more convenient and safe.
      42             :  *
      43             :  * `MutableSpan<T>` can be used when a function is supposed to return an array, the
      44             :  * size of which is known before the function is called. One advantage of this approach is that the
      45             :  * caller is responsible for allocation and deallocation. Furthermore, the function can focus on
      46             :  * its task, without having to worry about memory allocation. Alternatively, a function could
      47             :  * return an Array or Vector.
      48             :  *
      49             :  * NOTE: When a function has a MutableSpan<T> output parameter and T is not a trivial type,
      50             :  * then the function has to specify whether the referenced array is expected to be initialized or
      51             :  * not.
      52             :  *
      53             :  * Since the arrays are only referenced, it is generally unsafe to store a Span. When you
      54             :  * store one, you should know who owns the memory.
      55             :  *
      56             :  * Instances of Span and MutableSpan are small and should be passed by value.
      57             :  */
