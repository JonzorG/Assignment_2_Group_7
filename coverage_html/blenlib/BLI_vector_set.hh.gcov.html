       7             : /** \file
       8             :  * \ingroup bli
       9             :  *
      10             :  * A `VectorSet<Key>` is an ordered container for elements of type `Key`. It has the same
      11             :  * interface as `Set` with the following extensions:
      12             :  * - The insertion order of keys is maintained as long as no elements are removed.
      13             :  *   - Once elements are removed, the order of keys is only maintained for the elements added
      14             :  *     _before_ any removed element.
      15             :  * - The keys are stored in a contiguous array.
      16             :  *
      17             :  * All core operations (add, remove and contains) can be done in O(1) amortized expected time.
      18             :  *
      19             :  * Using a VectorSet instead of a normal Set can be beneficial in any of the following
      20             :  * circumstances:
      21             :  * - The insertion order is important.
      22             :  * - Iteration over all keys has to be fast.
      23             :  * - The keys in the set are supposed to be passed to a function that does not have to know that
      24             :  *   the keys are stored in a set. With a VectorSet, one can get a Span containing all keys
      25             :  *   without additional copies.
      26             :  *
      27             :  * VectorSet is implemented using open addressing in a slot array with a power-of-two
      28             :  * size. Other than in Set, a slot does not contain the key though. Instead it only
      29             :  * contains an index into an array of keys that is stored separately.
      30             :  *
      31             :  * Some noteworthy information:
      32             :  * - Key must be a movable type.
      33             :  * - Pointers to keys might be invalidated, when the vector set is changed or moved.
      34             :  * - The hash function can be customized. See BLI_hash.hh for details.
      35             :  * - The probing strategy can be customized. See BLI_probing_strategies.hh for details.
      36             :  * - The slot type can be customized. See BLI_vector_set_slots.hh for details.
      37             :  * - The methods `add_new` and `remove_contained` should be used instead of `add` and `remove`
      38             :  *   whenever appropriate. Assumptions and intention are described better this way.
      39             :  * - Using a range-for loop over a vector set, is as efficient as iterating over an array (because
      40             :  *   it is the same thing).
      41             :  * - Lookups can be performed using types other than Key without conversion. For that use the
      42             :  *   methods ending with `_as`. The template parameters Hash and IsEqual have to support the other
      43             :  *   key type. This can greatly improve performance when the strings are used as keys.
      44             :  * - The default constructor is cheap.
      45             :  * - The `print_stats` method can be used to get information about the distribution of keys and
      46             :  *   memory usage.
      47             :  */
