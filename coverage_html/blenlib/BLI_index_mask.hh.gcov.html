     174             : /**
     175             :  * An #IndexMask is a sequence of unique and sorted indices (`BLI_unique_sorted_indices.hh`).
     176             :  * It's commonly used when a subset of elements in an array has to be processed.
     177             :  *
     178             :  * #IndexMask is a non-owning container. That data it references is usually either statically
     179             :  * allocated or is owned by an #IndexMaskMemory.
     180             :  *
     181             :  * Internally, an index mask is split into an arbitrary number of ordered segments. Each segment
     182             :  * contains up to #max_segment_size (2^14 = 16384) indices. The indices in a segment are stored as
     183             :  * `int16_t`, but each segment also has a `int64_t` offset.
     184             :  *
     185             :  * The data structure is designed to satisfy the following key requirements:
     186             :  * - Construct index mask for an #IndexRange in O(1) time (after initial setup).
     187             :  * - Support efficient slicing (O(log n) with a low constant factor).
     188             :  * - Support multi-threaded construction without severe serial bottlenecks.
     189             :  * - Support efficient iteration over indices that uses #IndexRange when possible.
     190             :  *
     191             :  * Construction:
     192             :  *   A new index mask is usually created by calling one of its constructors which are O(1), or for
     193             :  *   more complex masks, by calling various `IndexMask::from_*` functions that create masks from
     194             :  *   various sources. Those generally need additional memory which is provided with by an
     195             :  *   #IndexMaskMemory.

     198             :  *   the function will only consider the indices in the "universe". The term comes from
