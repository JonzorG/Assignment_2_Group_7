      14             :  *
      15             :  * This is not a trivial problem because e.g. just storing a pointer to the socket a value
      16             :  * belongs to is not enough. That's because the same socket may correspond to many different values
      17             :  * when the socket is used in a node group that is used multiple times. In this case, not only does
      18             :  * the socket have to be stored but also the entire nested node group path that led to the
      19             :  * evaluation of the socket.
      20             :  *
      21             :  * Storing the entire "context path" for every logged value is not feasible, because that path can
      22             :  * become quite long. So that would need much more memory, more compute overhead and makes it
      23             :  * complicated to compare if two contexts are the same. If the identifier for a compute context
      24             :  * would have a variable size, it would also be much harder to create a map from context to values.
      25             :  *
