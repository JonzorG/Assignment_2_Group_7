      70             :  * \section bm_cycles BMesh Cycles
      71             :  *
      72             :  * NOTE(@joeedh): this is somewhat outdated, though bits of its API are still used.
      73             :  *
      74             :  * Cycles are circular doubly linked lists that form the basis of adjacency
      75             :  * information in the BME modeler. Full adjacency relations can be derived
      76             :  * from examining these cycles very quickly. Although each cycle is a double
      77             :  * circular linked list, each one is considered to have a 'base' or 'head',
      78             :  * and care must be taken by Euler code when modifying the contents of a cycle.
      79             :  *
      80             :  * The contents of this file are split into two parts. First there are the
      81             :  * bmesh_cycle family of functions which are generic circular double linked list
      82             :  * procedures. The second part contains higher level procedures for supporting
      83             :  * modification of specific cycle types.
      84             :  *
      85             :  * The three cycles explicitly stored in the BM data structure are as follows:
      86             :  * 1: The Disk Cycle - A circle of edges around a vertex
      87             :  * Base: vertex->edge pointer.
      88             :  *
      89             :  * This cycle is the most complicated in terms of its structure. Each bmesh_Edge contains
      90             :  * two bmesh_CycleNode structures to keep track of that edges membership in the disk cycle
      91             :  * of each of its vertices. However for any given vertex it may be the first in some edges
      92             :  * in its disk cycle and the second for others. The bmesh_disk_XXX family of functions contain
      93             :  * some nice utilities for navigating disk cycles in a way that hides this detail from the
      94             :  * tool writer.
      95             :  *
      96             :  * Note that the disk cycle is completely independent from face data. One advantage of this
      97             :  * is that wire edges are fully integrated into the topology database. Another is that the
      98             :  * the disk cycle has no problems dealing with non-manifold conditions involving faces.
      99             :  *
     100             :  * Functions relating to this cycle:
     101             :  * - #bmesh_disk_vert_replace
     102             :  * - #bmesh_disk_edge_append
     103             :  * - #bmesh_disk_edge_remove
     104             :  * - #bmesh_disk_edge_next
     105             :  * - #bmesh_disk_edge_prev
     106             :  * - #bmesh_disk_facevert_count
     107             :  * - #bmesh_disk_faceedge_find_first
     108             :  * - #bmesh_disk_faceedge_find_next
     109             :  * 2: The Radial Cycle - A circle of face edges (bmesh_Loop) around an edge
     110             :  * Base: edge->l->radial structure.
     111             :  *
     112             :  * The radial cycle is similar to the radial cycle in the radial edge data structure.*
     113             :  * Unlike the radial edge however, the radial cycle does not require a large amount of memory
     114             :  * to store non-manifold conditions since BM does not keep track of region/shell information.
     115             :  *
     116             :  * Functions relating to this cycle:
     117             :  * - #bmesh_radial_loop_append
     118             :  * - #bmesh_radial_loop_remove
     119             :  * - #bmesh_radial_facevert_count
     120             :  * - #bmesh_radial_facevert_check

     122             :  * - #bmesh_radial_faceloop_find_next
     123             :  * - #bmesh_radial_validate
     124             :  * 3: The Loop Cycle - A circle of face edges around a polygon.
     125             :  * Base: polygon->lbase.
     126             :  *
     127             :  * The loop cycle keeps track of a faces vertices and edges. It should be noted that the
     128             :  * direction of a loop cycle is either CW or CCW depending on the face normal, and is
     129             :  * not oriented to the faces edit-edges.
     130             :  *
     131             :  * Functions relating to this cycle:
