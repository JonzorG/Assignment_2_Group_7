      27             : /// ParamValue holds a named parameter and typed data. Usually, it owns the
      28             : /// data (holding it in the struct itself if small enough, dynamically
      29             : /// allocated for larger things), but it can also refer to non-owned data.
      30             : ///
      31             : /// The data is usually a single value of any type described by TypeDesc
      32             : /// (including arrays). It may also hold more than one value of the type --
      33             : /// this is usually only used in a geometric context, such as storing a value
      34             : /// for each vertex in a mesh. Please note the subtle distinction between the
      35             : /// value type itself being an array, versus having multiple values as a
      36             : /// parameter, versus the type of the value having multiple components (such
      37             : /// as a point or color). Any combination of these may be present.
      38             : ///
      39             : /// To clarify, if you have an array of 4 colors for each of 15 mesh
      40             : /// vertices, that means:
      41             : ///  - There are 15 VALUES (one for each vertex)
      42             : ///  - Each value has an array of 4 ELEMENTS
      43             : ///  - Each element is a color
      44             : ///  - A color has 3 COMPONENTS (R, G, B)
      45             : /// Thus, it would be constructed as
      46             : /// `ParamValue("mycolor", TypeDesc(TypeDesc::COLOR, 4), 15, ptr_to_data)`
      47             : ///
      48             : /// The main constructor is `ParamValue(name, type, nvalues, dataptr)`. It can
      49             : /// be confusing at first to remember that the data argument is a pointer to
      50             : /// the first values to copy, not the values themselves, even if the values
      51             : /// are themselves pointers, and even if the number of values is 1. In other
      52             : /// words, it's behaving as if you're always pointing it to an array even if
      53             : /// the "array" has only one element. This is extra confusing for strings,
      54             : /// because the strings themselves are `char*` (or ustring), so the pointer
      55             : /// you need to pass is `char**`. For this reason, there are also convenience
      56             : /// constructors for simple types such as a single int, float, or string.
      57             : ///
      58             : /// So here are some examples:
      59             : ///
      60             : ///     // Single int:
      61             : ///     int my_int = 42;
      62             : ///     ParamValue A("foo", TypeDesc::INT, 1, make_cspan(my_int));
      63             : ///     // Three int values (say, one per vertex of a triangle):
