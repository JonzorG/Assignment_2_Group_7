     103             :  *
     104             :  * A wl_message describes the signature of an actual protocol message, such as a
     105             :  * request or event, that adheres to the Wayland protocol wire format. The
     106             :  * protocol implementation uses a wl_message within its demarshal machinery for
     107             :  * decoding messages between a compositor and its clients. In a sense, a
     108             :  * wl_message is to a protocol message like a class is to an object.
     109             :  *
     110             :  * The `name` of a wl_message is the name of the corresponding protocol message.
     111             :  *
     112             :  * The `signature` is an ordered list of symbols representing the data types
     113             :  * of message arguments and, optionally, a protocol version and indicators for
     114             :  * nullability. A leading integer in the `signature` indicates the _since_
     115             :  * version of the protocol message. A `?` preceding a data type symbol indicates
     116             :  * that the following argument type is nullable. While it is a protocol violation
     117             :  * to send messages with non-nullable arguments set to `NULL`, event handlers in
     118             :  * clients might still get called with non-nullable object arguments set to
     119             :  * `NULL`. This can happen when the client destroyed the object being used as
     120             :  * argument on its side and an event referencing that object was sent before the
     121             :  * server knew about its destruction. As this race cannot be prevented, clients
     122             :  * should - as a general rule - program their event handlers such that they can
     123             :  * handle object arguments declared non-nullable being `NULL` gracefully.
     124             :  *
     125             :  * When no arguments accompany a message, `signature` is an empty string.
     126             :  *
     127             :  * Symbols:
     128             :  *
     129             :  * * `i`: int
     130             :  * * `u`: uint
     131             :  * * `f`: fixed
     132             :  * * `s`: string
     133             :  * * `o`: object
     134             :  * * `n`: new_id
     135             :  * * `a`: array
     136             :  * * `h`: fd
     137             :  * * `?`: following argument (`o` or `s`) is nullable
     138             :  *

     141             :  * implementation often must determine the type of the object. The `types` of a
     142             :  * wl_message is an array of wl_interface references that correspond to `o` and
